# ADR-001 — Деплой на Vercel (free)

Дата: 2026-04-16

## Контекст
Нужно быстро и дешево (на старте — бесплатно) развернуть MVP:
- Web‑клиент (React+Vite) с роутами `/` и `/admin`.
- Backend API (Fastify) под префиксом `/api/*`.

## Решение
Используем Vercel как хостинг:
- Frontend деплоим как статическую сборку Vite.
- Backend запускаем как Vercel Serverless Function, которая проксирует запросы в Fastify‑приложение.

В репозитории за это отвечают:
- `vercel.json` — конфигурация Vercel сборки и маршрутизации.
- `api/[...path].ts` — serverless‑адаптер, который обслуживает все запросы `/api/*`.

## Почему так
Плюсы:
- быстрый деплой без собственного сервера,
- один домен для UI и API (удобно для CORS/куки),
- бесплатный старт.

Минусы/риски:
- serverless ограничения по времени выполнения и по размеру тела запросов,
- cold starts (первый запрос медленнее),
- для тяжёлой обработки изображений может потребоваться оптимизация/очередь.

## Переменные окружения (Vercel)
Минимум:
- `DATABASE_URL` — строка подключения к Postgres (рекомендуемо Neon/Supabase на бесплатном тарифе).

Опционально (когда подключим object storage):
- токены/ключи Blob‑хранилища (зависит от выбранного провайдера).

## Настройки проекта в Vercel (UI)
Рекомендуемая конфигурация:
- Root Directory: репозиторий целиком (корень).
- Install Command: `npm install`
- Build Command: `npm run build --workspace apps/web`
- Output Directory: `apps/web/dist`

## Что проверить после деплоя
- Открывается UI по `/`.
- Роут `/admin` открывается по прямой ссылке (SPA‑fallback работает).
- `GET /api/health` возвращает `{ ok: true }`.

## Примечание про SPA‑fallback
SPA‑fallback реализован через `rewrites` в `vercel.json`, которые направляют все запросы,
не начинающиеся с `/api/`, на `/index.html`.

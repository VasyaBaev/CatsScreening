# ADR-002 — Хранение данных: Postgres + object storage

Дата: 2026-04-16

## Контекст
MVP хранит “кейсы”:
- метаданные анкеты/условий съёмки,
- ссылки на эталонное и диагностическое фото,
- результат скоринга (score/confidence),
- QC‑флаги (blur/glare/dark).

Изображения с камеры смартфона могут быть большими. В serverless‑окружении загрузка “байтами через API” часто упирается в ограничения по размеру запроса.

## Решение
Делим хранение на две части:
1) Postgres — хранит структуру кейса и метаданные, а также ссылки на изображения.
2) Object storage — хранит сами файлы изображений (оригиналы и, позже, превью/thumbnail).

## Почему не класть фото в БД
- Это дорого и неэффективно по размеру/производительности.
- Проще масштабировать объектное хранилище отдельно.

## Паттерн загрузки в проде (будущий)
1) Клиент получает “разрешение”/URL на upload (или прямой upload‑URL).
2) Клиент грузит файл напрямую в object storage.
3) Клиент отправляет в API только `uri`/`key` + метаданные.

## Что хранится в Postgres
- `Case.metadata` (JSON)
- `Case.score`, `Case.confidence`
- `Case.qc` (JSON)
- `CaseImage.kind` + `CaseImage.uri`
